# SavdEx — памятка для Claude

Каждый новый чат читает этот файл сам. Здесь — что где лежит, как код
попадает на сайт и правила работы с владельцем. Подробности — по ссылкам.

**SavdEx** (savdex.uz) — B2B-площадка для Узбекистана и Центральной Азии:
поставщики и закупщики находят друг друга по объявлениям и карточкам
компаний. Зарабатывает на раскрытии контактов, подписках и продвижении.

**База команды** — приватный репозиторий `Tem4ik69/savdex-team`
(Obsidian): куда развиваемся, решения, планы, идеи, кто чем занят. В
этом чате его нет — подключить (add_repo) и начать с `00 Старт.md`, затем
`SavdEx/SavdEx.md` и `SavdEx/Дорожная карта SavdEx.canvas`. У каждого
проекта команды там своя папка, SavdEx — `SavdEx/`; правила базы — её
`CLAUDE.md`. Команда видит базу в Obsidian: что попало в её ветку `main`,
через пару минут у всех. Поэтому каждый чат ведёт свою работу там сам —
коммитом прямо в `main` базы, без PR:

- взялся за задачу — карточка в колонке «Сейчас» дорожной карты SavdEx:
  что делаем и номер PR, когда он появится;
- PR влит — карточка в «Сделано», строка в журнал месяца
  (`SavdEx/Журнал/ГГГГ-ММ.md`) со ссылкой на PR;
- принято решение — заметка в `SavdEx/Решения/` и строка в
  `SavdEx/SavdEx.md`; новый план или идея — в направление SavdEx или в
  `Идеи.md`.

Перед правкой — `git pull`: заметки правят и люди.

## Правила работы

- **Отвечать по-русски.** Коммиты и описания PR — тоже по-русски; без
  названий и версий моделей.
- **«Стой», «стоп», «остановись» — остановиться сразу.**
- **Репозиторий публичный: код и журналы Actions видят все.** Никаких
  паролей, ключей, токенов, адресов сигналов (ping URL) в коде,
  коммитах, журналах. Владельца просить не присылать их в чат — только в
  секреты GitHub.
- **Персональные данные граждан Узбекистана не покидают Узбекистан.**
  Мониторинг отдаёт наружу только цифры, без журналов; копии базы — в
  хранилище Uztelecom; проверки с данными — на машинах в Ташкенте.
- **Основная ветка `claude/website-copy-new-design-xaxsr0`** — только
  через PR. Влить — только после явного «мержи» владельца и зелёного
  CI; PR только с документацией (без кода, выкладки, машин) — можно
  влить и без «мержи», как только CI зелёный. Перед PR — проверки
  (ниже); тесты не отключать и не пропускать.
- Чужие ветки (других чатов) — не пушить без разрешения; не
  переписывать историю (rebase, force-push) на чужих ветках.
- **Релиз на боевые машины жмёт только владелец** (Actions → prod). Моё
  дело — сказать, когда можно и что уедет, и проверить итог.
- Стереть или заменить данные тестового или боевого — только после
  явного «да».
- Не перезагружать и не обновлять ОС тестового сервера.
- Не публиковать подробности уязвимости до исправления.
- Кода Laravel/PHP больше нет и не возвращать: всё на Python.
- Ящик Zoho не трогать, пока он не оплачен.
- Канареечный релиз — отложен (docs/backlog.md, раздел 8): не
  напоминать, но если спросят — сразу понять, о чём речь.

## Как код попадает на сайт

1. Ветка → PR в основную ветку. Обязательная проверка — одна, **«CI»**
   (Python: разбор, типы, тесты; TypeScript; сборка образа).
2. Слияние → после зелёного CI основная ветка сама выкладывается на
   **тестовый** `staging.savdex.uz` (под паролем, свои демо-данные) и,
   пройдя проверку снаружи, становится **кандидатом** в релиз.
3. **Релиз** — кнопкой владельца, Actions → prod: кандидат, тот же образ
   с тестового, копия базы перед схемой, админка, сайт, проверка
   снаружи, агенты мониторинга. Галочка «проверить восстановление» —
   подъём ночной копии базы во временной базе.
4. Посмотреть ветку до слияния — **превью** `preview.savdex.uz`
   (Actions → preview, имя ветки в «ref»): только то, что видно в
   браузере; выкладку и машины превью не проверяет.

## Машины (Uztelecom Cloud, Ташкент)

| Машина | Что |
|---|---|
| `savdex-web` | Caddy (HTTPS) и сайт; единственный внешний адрес боевых машин |
| `savdex-admin` | админка и фоновые задачи; только частная сеть |
| `savdex-db` | PostgreSQL 18, общая папка файлов (NFS), резервные копии в S3; только частная сеть |
| тестовый | `staging.savdex.uz` и `preview.savdex.uz` |

Копии: база — каждую ночь в 03:40, файлы — каждый час, проверка
восстановления — в 05:10. Сигналы — в Healthchecks.io. Тревоги — в
Telegram-группу «Вайбкодеры»: UptimeRobot (сайт снаружи), Healthchecks
(копии), Grafana Cloud (машины, база, сайт; бот @savdex_alerts_bot).

## Проверки перед PR

```bash
cd python
uv sync --all-groups
uv run ruff check . && uv run ruff format --check . && uv run mypy savdex
SAVDEX_PARITY_PG_URL=postgres://…/savdex_test uv run pytest -q   # в имени базы — «test»
npx tsc --noEmit                                                  # из корня
```

Скрипты `deploy/` — `bash -n` и `shellcheck`; workflows — `actionlint`.
Изменения выкладки, машин и мониторинга проверяются на стенде из
контейнеров (Docker) — превью их не показывает.

## Частые ловушки

- `команда | grep -q` под `set -o pipefail` — ложный сбой (SIGPIPE, код
  141): сначала вывод в переменную, потом `grep -q … <<< "$var"`.
- Файлы, скопированные в образ, сохраняют права: выписанное под
  `umask 077` не прочитает www-data.
- Журналы Actions публичные: почты, телефоны, строки данных из базы в
  них не выводить.
