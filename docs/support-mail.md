# Письма в поддержку → обращения

Письмо клиента на ящик поддержки становится обращением в админке
(«CRM» → «Обращения»), ответ поддержки уходит клиенту письмом, а его ответ
на это письмо возвращается в то же обращение. Код —
`python/savdex/support/mail.py`, проверки — `python/tests/test_support_mail.py`.

## Как работает

**Входящие.** Раз в минуту фоновый обработчик (`manage.py notify`) читает
непрочитанные письма ящика поддержки по IMAP:

- **новое письмо** → обращение с каналом «Почта»: тема, имя и почта
  отправителя, текст. Если на SavdEx есть пользователь с этой почтой,
  обращение сразу привязано к нему и его компании;
- **ответ клиента** на наше письмо (или письмо с номером в теме «[№123]»)
  → сообщение в то же обращение. Цитата прошлой переписки отрезается.
  Ждавшее клиента или закрытое обращение снова становится «Открыто»
  (или «В работе», если у него есть ответственный). Только если пишет тот
  же человек: чужое письмо с подсмотренным номером заводит своё обращение;
- **вложения** сохраняются в закрытое хранилище (до 10 файлов, до 10 МБ
  каждый, до 25 МБ на письмо) и скачиваются со страницы обращения. Мелкие
  картинки (логотипы в подписях) пропускаются;
- **пропускаются** автоответы («Я в отпуске»), рассылки и письма от самих
  себя. **Отказ доставки** нашего ответа («адрес не существует») —
  внутренней заметкой в обращение: видно, что клиент ответа не получил;
- одно и то же письмо дважды не заводится. Обработанное письмо в ящике
  помечается прочитанным, письмо, которое не удалось разобрать, — ещё и
  флажком: его стоит открыть в самом ящике.

**Ответ.** «Ответить» на странице обращения (без галочки «внутренняя
заметка») — письмо клиенту: тема «Re: … [№123]», от «SavdEx — поддержка»
с адреса поддержки, внизу номер обращения. Под ответом видно, ушло ли
письмо и когда, или почему нет. Почта клиента берётся из обращения, иначе
из его учётной записи; если почты нет, ответ сохраняется только в админке
(форма об этом предупреждает).

## Что нужно настроить

1. **Ящик поддержки с доступом по IMAP**, куда приходят письма на адрес
   поддержки (в настройках площадки — «Почта поддержки», сейчас
   `support@savdex.uz`). Подойдёт любой почтовый сервис: Zoho Mail,
   Яндекс 360, Google Workspace, почта хостинга. Сайт читает ящик сам —
   людям туда заходить не обязательно, но можно: обработанные письма там
   просто прочитаны.
2. **Render → Environment** (только в панели, не в `render.yaml`):

   | Переменная | Значение |
   |---|---|
   | `SUPPORT_IMAP_HOST` | IMAP-сервер ящика: `imappro.zoho.com` (Zoho, платный ящик на своём домене), `imap.yandex.ru`, `imap.gmail.com` |
   | `SUPPORT_IMAP_USERNAME` | адрес ящика, например `support@savdex.uz` |
   | `SUPPORT_IMAP_PASSWORD` | пароль приложения ящика |
   | `SUPPORT_IMAP_PORT` | по желанию, по умолчанию `993` |
   | `SUPPORT_IMAP_FOLDER` | по желанию, по умолчанию `INBOX` |

3. **Отправка ответов** — через почту сайта (Brevo, `MAIL_*`) от адреса
   поддержки. В Brevo адрес должен быть разрешённым отправителем: домен
   savdex.uz подтверждён, при отказе — добавить адрес в Senders. Свой
   почтовик для ответов (например, SMTP самого ящика поддержки) задаётся
   переменными `SUPPORT_MAIL_MAILER=smtp`, `SUPPORT_MAIL_HOST`,
   `SUPPORT_MAIL_PORT`, `SUPPORT_MAIL_USERNAME`, `SUPPORT_MAIL_PASSWORD`;
   адрес «От кого» — `SUPPORT_MAIL_FROM_ADDRESS`, если он не совпадает с
   «Почтой поддержки».

Пока `SUPPORT_IMAP_*` не заданы, ящик не читается; ответы клиентам
уходят и без этого.

## Вручную

- `manage.py support_mail` — один проход по ящику прямо сейчас;
- `manage.py support_mail --eml письмо.eml` — завести обращение из
  сохранённого письма (например, пересланного вложением).
