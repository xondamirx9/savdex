# Мини-сайты компаний

Своя страница у каждой компании на тарифе с мини-сайтом (`has_microsite`:
Business, Premium, VIP), в её цветах и шрифтах.

Два режима адреса, выбор — переменная `MICROSITE_DOMAIN`:

| `MICROSITE_DOMAIN` | Адрес сайта |
|---|---|
| не задана (сейчас) | `savdex.uz/s/acme` — страница самой площадки |
| `savdex.site` | `acme.savdex.site` — свой поддомен |

Адрес компании (`company_sites.subdomain`) в обоих режимах один. При
переходе на домен `savdex.uz/s/acme` отвечает постоянным перенаправлением
на `acme.savdex.site`: ссылки, разосланные раньше, не ломаются.

Пока компании не пишут свой CSS и JS, страница на домене площадки
безопасна. Свой CSS — повод сначала перейти на отдельный домен
(см. ниже).

## Как устроено

**Сайт не хранит содержимого.** Товары, контакты, документы и отзывы
берутся из карточки компании. В `company_sites` лежат только адрес
и оформление. Компания ведёт всё в одном месте, и объявление,
добавленное в кабинете, сразу появляется и на её сайте.

| Что | Где |
|---|---|
| Адрес и оформление | `company_sites`, модель `CompanySite` |
| Токены, шаблоны, контраст | `App\Support\Microsite\SiteTheme` |
| Разбор хоста, адреса | `App\Support\Microsite\SiteHost`, `config/microsite.php` |
| Данные страницы | `App\Support\Microsite\SitePage` — одна сборка для сайта и предпросмотра |
| Сайт для посетителей | `Microsite\SiteController`: `/s/{subdomain}` и `{subdomain}.savdex.site` |
| Редактор | `Cabinet\SiteController`, страница `cabinet/Site` |
| Вёрстка | `pages/site/Show.tsx`, `resources/css/microsite.css`, `views/microsite.blade.php` |

**Черновик и опубликованное — отдельно.** «Сохранить» меняет `theme`,
посетители видят `published_theme`, пока компания не нажмёт
«Опубликовать».

**Сайт открыт, только пока выполнены все три условия**: он опубликован,
компания не заблокирована, действующий тариф включает мини-сайт.
Кончилась подписка — сайт отвечает 404 сам, без регламентной команды.

**Контакты на мини-сайте открыты.** На карточке площадки за них платит
покупатель, но мини-сайт — собственная страница компании, оплаченная её
тарифом. Сайт со спрятанным телефоном компании не нужен.

**На домене мини-сайтов открыт только сам мини-сайт** (в режиме поддоменов). Маршруты площадки
к домену не привязаны, поэтому `RestrictSiteHost` пропускает белый список
путей (`/`, `robots.txt`, `up`, `files/*`). Иначе `acme.savdex.site/login`
показывал бы вход в SAVDEX на адресе компании.

**Отдельный домен, а не `*.savdex.uz`.** Куки площадки на `savdex.site`
браузер не отправит. Страница, оформленная компанией, не окажется рядом
с сессией SAVDEX.

## Переход на свой домен

Сейчас ничего настраивать не нужно: сайты работают на `savdex.uz/s/…`.
Когда домен понадобится:

1. Купить домен `savdex.site`.
2. DNS: `*.savdex.site` и `savdex.site` направить CNAME/ALIAS на сервис
   Render (адрес `savdex.onrender.com`).
3. Render → сервис → Settings → Custom Domains: добавить
   `*.savdex.site` и `savdex.site`. Для wildcard Render попросит
   подтверждающие записи `_acme-challenge` — их добавить в DNS, сертификат
   выпустится сам.
4. Задать переменную окружения `MICROSITE_DOMAIN=savdex.site` и
   перезапустить сервис.

Локально без переменной сайт открывается на `http://localhost:8000/s/acme`.
Проверить поддомены: `MICROSITE_DOMAIN=site.localhost`, сайт — на
`http://acme.site.localhost:8000`. Просто `localhost` не годится: площадка
на нём же попала бы под `RestrictSiteHost`.

## Что дальше

- **Форма заявки** на сайте. Сейчас посетитель звонит или пишет напрямую.
  Заявка в чат площадки нужна новой таблицей: у анонимного посетителя
  нет компании, а `MessageThread` связывает две компании.
- **Своя страница товара** на мини-сайте. Сейчас карточка товара ведёт
  на площадку.
- **Свой домен компании** (`www.acme.uz`) — для VIP. Кастомных доменов на
  один сервис у Render ограниченное число, поэтому для масштаба нужен
  Cloudflare for SaaS (Custom Hostnames): он выпускает сертификат на каждый
  домен клиента, домен добавляется вызовом API из кабинета. В
  `company_sites` добавить `custom_domain` и `domain_verified_at`,
  в `RestrictSiteHost` и маршрутизации — поиск сайта по полному хосту.
- **Модерация**: раздел в админке со списком сайтов и кнопкой снятия
  с публикации. Сейчас сайт выключается блокировкой компании.

## Свой CSS: как делать, когда дойдёт

Решено пока ограничиться токенами и шаблонами. Если понадобится свой
CSS (для VIP), вот безопасный порядок.

**Сначала — отдельный домен.** На `savdex.uz/s/…` чужой CSS оказался бы
на одном адресе с кабинетом и сессией площадки. Свой CSS включается
только вместе с `MICROSITE_DOMAIN`.

**Чего не делать никогда:** свой HTML и JavaScript. Это прямой путь к
фишингу и краже данных посетителей, и никакая фильтрация от этого
надёжно не защищает.

**Как хранить и отдавать CSS:**

1. Отдельное поле `custom_css` (text, до 20 КБ) в черновике и
   опубликованной версии, как у темы.
2. Разбирать CSS парсером (`sabberworm/php-css-parser`), а не
   регулярками, и собирать заново из разобранного. Строка компании
   в `<style>` дословно не попадает.
3. Каждый селектор префиксовать `.ms-root` — стили не выходят за
   пределы сайта и не задевают отметку SAVDEX в подвале.
4. Запретить:
   - `@import`, `@font-face`, `@charset`, `@namespace`;
   - любые `url()`, кроме файлов из хранилища площадки (загрузка картинок
     через кабинет) — иначе CSS становится трекером посетителей;
   - `expression()`, `behavior`, `-moz-binding`, `javascript:`;
   - `position: fixed` и `z-index` выше порога — чтобы нельзя было
     накрыть страницу поддельной формой входа.
5. Подвал с отметкой SAVDEX защитить: `!important` на его `display`,
   `visibility` и `opacity`, либо рендерить его вне `.ms-root`.
6. Отдавать сайты с заголовком
   `Content-Security-Policy: default-src 'self'; img-src 'self' data: https:; style-src 'self' 'unsafe-inline' fonts.bunny.net; font-src fonts.bunny.net; script-src 'self'; frame-ancestors 'self' https://savdex.uz`.
   Даже если фильтр что-то пропустит, браузер не загрузит чужой ресурс.
7. В редакторе — `<textarea>` с подсветкой и списком классов
   (`.ms-hero`, `.ms-tile`, `.ms-card`…), которые считаются стабильным
   API. Классы вне списка можно переименовывать без предупреждения.
8. Модерация: сайты со своим CSS помечать в админке, изменение CSS
   публиковать только после просмотра модератором — хотя бы первые
   месяцы.

Промежуточный шаг, который закрывает большинство запросов без рисков
своего CSS: больше токенов (ширина контейнера, стиль карточек — рамка,
тень или заливка, размер заголовков, свой фон первого экрана из
загруженных картинок) и больше вариантов у каждого блока.
