# Python-половина SavdEX

Каркас Django, с которого начинается перенос площадки с Laravel.
Зачем и в каком порядке — [docs/migration-to-python.md](../docs/migration-to-python.md).

Сейчас здесь **нет ни строки кода площадки**. Это этап 0: каркас,
предохранители и проверки. Приложение отвечает на один адрес — `/up`.

## Запустить у себя

Нужен [uv](https://docs.astral.sh/uv/) и Python 3.11 или новее.

```sh
cd python
uv sync --all-groups
uv run pytest -q          # 24 проверки, должны пройти
uv run ruff check .
uv run mypy savdex
```

Базы для проверок не нужно: они идут на SQLite в памяти.

Чтобы поднять само приложение, нужна та же база, с которой работает
Laravel, — через `DATABASE_URL` или через переменные `DB_HOST`,
`DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` (те же имена,
что в `.env` у PHP; двух наборов имён для одной базы быть не должно).

```sh
DATABASE_URL=postgres://... uv run python manage.py runserver
```

## Что здесь лежит

| Файл | Зачем |

## Предохранители

`savdex/guards.py` закрепляет в коде два правила переноса, которые
иначе держались бы только на памяти людей.

**Запись в чужую таблицу отказывает.** Пока таблица принадлежит
Laravel, Django её только читает. Не договорённость, а обёртка вокруг
каждого запроса к базе: ловит и ORM, и `cursor.execute`.

Так это выглядит:

```
WriteToForeignTableError: Таблица «listings» принадлежит Laravel,
Django её только читает (правило 4.1 в docs/migration-to-python.md).
Если её хозяин действительно переходит — сначала перенесите правила
модели из раздела 5, потом добавьте таблицу в OWNED_TABLES.
```

Причина строгости — раздел 5 документа. Половина правил площадки живёт
в событиях моделей Eloquent: пересчёт рейтинга компании, запрет
возвращать отклонённое объявление на витрину, сброс устаревших
переводов у резюме. Код на Django, который пишет в те же таблицы
напрямую, обойдёт их **молча**. Ошибка проявится не сразу и не громко —
расхождением данных через месяц.

**Схему базы меняет только Laravel.** `manage.py migrate` не делает
ничего: маршрутизатор `LaravelOwnsSchema` запрещает миграции, а `CREATE`
и `ALTER` не проходят предохранитель. Все изменения структуры базы идут
через `database/migrations` у PHP — до самого конца переноса.

### Как передать таблицу Django

Одна строка в `OWNED_TABLES`, но перед ней — три условия:

1. Правила модели из раздела 5 документа перенесены;
2. На них написаны проверки pytest, и они **падают** без переноса;
3. Laravel в эту таблицу больше не пишет.

Порядок, в котором таблицы переходят, — раздел 6 документа.

Предохранитель — второй замок, а не первый. Первый — роль в PostgreSQL
без права записи, её выдаёт тот, кто настраивает Render. Код можно
обойти, права базы — нет.

## Чего здесь намеренно нет

- **Приложений Django** `auth`, `sessions`, `contenttypes`. Каждому
  нужны свои таблицы, а таблицы здесь заводит Laravel. Появятся
  на этапах 5 и 6.
- **Моделей.** Их сгенерирует `manage.py inspectdb` по существующей
  базе, когда будет доступ к копии боевой. Писать руками то, что уже
  описано в 74 миграциях, незачем.
- **Кода площадки.** Первая настоящая работа — этап 1, раздел 8
  документа: команда `savdex:check-postgres`, только чтение.
